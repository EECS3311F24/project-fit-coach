## Unfinished Tasks

After completing Sprint 1, we identified some tasks that still need further work. These tasks are important to enhance the user experience and align with our project goals, and we plan to address them in the upcoming sprint.

### 1. Implement a Formula Calculator for Different Weight Units (Pounds, Kilograms, Stones)
- **Story:** As a user, I want the ability to convert my weight between pounds, kilograms, and stones, allowing me to use the metric I’m most comfortable with.
- **Acceptance Criteria:** The system should offer a calculator function that lets users input their weight in one unit and view the equivalent in other units.

### 2. Add a Toggle Button for Weight Unit Selection
- **Story:** As a user, I want a button to choose my preferred weight unit for both input and display, which will improve the personalization of my experience.
- **Acceptance Criteria:** Users can easily switch between weight units (pounds, kilograms, or stones), and the chosen unit should be retained during their session.

### 3. Introduce Customizable Page Colors with Preset Templates
- **Story:** As a user, I would like the option to select different color themes beyond the standard dark/light mode, so that I can personalize the look of the app.
- **Acceptance Criteria:** Users can choose from a set of color templates, with their selection applied immediately to the interface.

*Note:* While we currently have a dark/light mode toggle, this task aims to provide additional color options for a more customizable experience.

## Practices to Continue

### 1. Regular Team Check-ins
Frequent meetings have been essential for keeping us on the same page and addressing any issues early. This practice has been effective, and we plan to continue it in future sprints to maintain strong communication.

### 2. Collaborative Learning
Working together to learn new technologies, such as JavaScript, Python, HTML, and CSS, has been invaluable. By supporting each other, we were able to overcome knowledge gaps and complete tasks more efficiently. We plan to continue this collaborative approach, especially as we tackle more complex features.

---

## New Practices to Consider

### 1. Mini Code Reviews
To improve code quality and avoid potential issues, we plan to incorporate short code review sessions. This will help ensure that everyone’s work aligns with the project standards and reduce technical debt.

### 2. Increased Pair Programming
We found that pairing up on tasks helped us solve problems faster and with fewer misunderstandings. We aim to incorporate more pair programming in the next sprint, especially for tasks that involve both frontend and backend integration.

---

## Practices to Avoid

### Working in Isolation
At times, we found ourselves working independently without enough communication, which occasionally led to integration challenges. Moving forward, we aim to work more collaboratively to ensure better alignment and avoid misunderstandings.

---

## Best/Worst Experiences During Sprint 1

- **Best Experience:** The highlight of Sprint 1 was successfully implementing the login feature, knowing that each user’s information was secure and properly handled. Seeing this feature in action was rewarding and gave us confidence in our progress.
  
- **Most Challenging Experience:** Debugging the calendar view for responsiveness was one of the more challenging aspects of this sprint. Ensuring the layout worked across different screen sizes took longer than anticipated, but it was a valuable learning experience about the importance of early testing for mobile compatibility.
